## Key learnings
- **Ableton Extension SDK shape:** TypeScript + vite + a `build.ts` per extension; outputs `.ablx` packages; uses `manifest.json` + `.env` (`EXTENSION_HOST_PATH`) to bind to the Live extension host.
- **SDK constraints worth remembering:** no submenus (flat items only), no "selected notes" API, no keyboard-shortcut binding, no `unregister` on `registerCommand` (so you use a fixed-size command pool reading a live map). `registerContextMenuAction` *does* return an unregister handle, so context-menu items can be live-rebuilt.
- **Host gotchas that cost time:** Developer Mode must be ON in Live Prefs; only one extension host may be connected at a time (kill the other before `npm start`); requires Node 24; `.env` and `node_modules` are gitignored so fresh checkouts need both recreated.
- **Terraform toolkit grew:** Hetzner-style sandbox, Docker sandbox, LocalStack S3 lab, and a `terraform.md` cheatsheet — all from Thursday, plus a `screen.md` cheatsheet drafted Friday.
- **Watch-Party versioning policy:** patch-bumps-only is now locked into project memory (Thursday's `6f85fb7`).
- **`dist-extensions/`** as a centralized compiled-output folder at the repo root (instead of per-extension `dist/`s) makes the install story simpler — one place to find every `.ablx` to drop into Live.
